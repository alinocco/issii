# Отчёт по лабораторной работе 1

### Тема: Предобработка данных (тревожность и ментальное здоровье)

## 1. Датасет

- Источник: Kaggle, датасет по тревожности и ментальному здоровью  
  (например, `Mental Health Data (Anxiety)`).
- Содержание: демографические признаки, ответы на вопросы опросника
  (шкалы тревожности, стресса, сна, социальной поддержки и т.п.), а также
  дополнительные факторы образа жизни.
- Формат: один или несколько CSV-файлов, размещённых локально в `lab1/data/raw/`
  и затем загруженных в MinIO в префикс `raw/`.

После загрузки сырых CSV в MinIO используется бакет `mental-health-lake` со
следующей логикой префиксов:

- `raw/` — исходные сырые CSV с ответами опроса;
- `staging/` — промежуточные parquet-файлы с уже построенными признаками;
- `processed/` — финальный датасет для обучения модели;
- `increment/` — файлы для инкрементальной дозагрузки новых респондентов.

## 2. Постановка задачи ML (после предобработки)

- **Задача**: бинарная классификация — предсказать повышенную тревожность респондента
  по совокупности его ответов и сопутствующих факторов.
- **Целевая переменная**:
  - либо берётся из готовой колонки (если она есть в исходном датасете);
  - либо строится автоматически как `anxiety_binary` на основе агрегированной
    шкалы `anxiety_score` (см. `scripts/preprocess_survey.py`).
- **Метрики**:
  - основная — F1-score, чтобы сбалансировать Precision/Recall;
  - дополнительные — ROC-AUC, Precision, Recall (используются в lab2).

## 3. Хранилище обработанных данных

- Выбрано: **MinIO** (локально в Docker), S3-совместимое хранилище.
- Обоснование:
  - стандартный паттерн data lake: отдельные слои для сырых, промежуточных и итоговых данных;
  - доступ через `boto3`/`s3fs` совместим с облачными S3 (AWS, Yandex Object Storage и др.);
  - лёгкий развёртывание в Docker Compose (без зависимости от облака).
- Структура бакета `mental-health-lake`:
  - `raw/` → сырые CSV,
  - `staging/` → признаки после предобработки,
  - `processed/` → финальный датасет `final_anxiety_dataset.parquet`,
  - `increment/` → файлы для дозагрузки (например, `anxiety_increment.parquet`).

## 4. Предобработка и инструменты

### Этапы и используемые инструменты

| Этап                      | Инструмент                         | Содержание                                                                                           |
|---------------------------|------------------------------------|------------------------------------------------------------------------------------------------------|
| Загрузка в MinIO         | `python scripts/download_raw_data.py` | Читает все CSV из `data/raw/` и выгружает их в MinIO в префикс `raw/`.                              |
| Работа с MinIO           | `scripts/minio_utils.py`           | Утилиты на базе `boto3`/`pandas` для чтения/записи parquet и CSV, листинга ключей, предпросмотра.  |
| Предобработка опроса     | `pandas` (`scripts/preprocess_survey.py`) | Очистка пропусков, построение шкал тревожности/стресса/сна, формирование бинарной цели, дедупликация по респонденту. |
| Инкрементальная загрузка | `pandas` (`scripts/load_increment.py`) | Чтение новых файлов из `increment/`, объединение с финальным датасетом, дедупликация по ID.        |

Первичный анализ (EDA) может быть оформлен в ноутбуке `notebooks/eda_anxiety.ipynb`:
там удобно исследовать распределения ответов и взаимосвязи между шкалами до выноса
логики в скрипт `preprocess_survey.py`.

### Ключевые шаги предобработки (preprocess_survey.py)

По результатам EDA и общим здравым практикам предобработки опросов реализованы
следующие шаги:

- **Очистка структуры**:
  - удаление полностью пустых столбцов;
  - поиск/создание идентификатора респондента (`respondent_id` по умолчанию).
- **Работа с типами и пропусками**:
  - выделение числовых и категориальных признаков;
  - заполнение пропусков в числовых колонках медианой;
  - заполнение пропусков в категориальных колонках значением `"unknown"`.
- **Агрегированные шкалы**:
  - поиск числовых колонок, содержащих ключевые слова в имени:
    - `"anxiety"` → `anxiety_score`,
    - `"stress"` → `stress_score`,
    - `"sleep"` / `"insomnia"` → `sleep_quality_score` / `insomnia_score`,
    - `"support"` → `support_score`,
    - `"depress"` → `depression_score`.
  - по каждой найденной группе строится среднее значение по строке.
- **Формирование бинарной цели**:
  - если уже существует колонка с именем, заданным переменной окружения `TARGET_COLUMN`
    (по умолчанию `anxiety_binary`), она используется как целевая;
  - иначе, при наличии `anxiety_score` строится `anxiety_binary` по медиане:
    значения ≥ медианы считаются повышенной тревожностью.
- **Дедупликация по респонденту**:
  - явные дубликаты по идентификатору респондента удаляются (оставляется одна запись).

Финальный датасет сохраняется в:
- `staging/anxiety_features.parquet` — для валидации в DAG;
- `processed/final_anxiety_dataset.parquet` — для обучения модели в lab2.

## 5. Оркестрация (Apache Airflow)

- DAG: `anxiety_preprocessing_pipeline` (`dags/anxiety_preprocessing_pipeline.py`).
- Схема:
  - проверка сырых данных в MinIO (`check_raw_data`);
  - предобработка опроса (`survey_preprocess`);
  - валидация результата в staging (`validate_staging`);
  - ветвление по наличию файлов в `increment/` (`check_increment`);
  - при наличии инкремента — дозагрузка (`load_increment`);
  - завершение пайплайна (`pipeline_complete`).
- Расписание: `@daily` — демонстрация регулярного запуска.
- Развёртывание: Docker Compose (`docker-compose.yml`, образ Airflow с зависимостями),
  PostgreSQL для метаданных Airflow, веб-интерфейс Airflow на порту хоста `8081`,
  MinIO UI на порту `9001`.

## 6. Инкрементальная загрузка

- Требование задания: дозагружать новые данные и объединять их с уже обработанными.
- Реализация:
  - скрипт `scripts/load_increment.py` ищет новые `.csv`/`.parquet` в `increment/`,
    читает их, объединяет с текущим `processed/final_anxiety_dataset.parquet`,
    выполняет дедупликацию по идентификатору респондента и сохраняет обновлённый
    датасет по тому же ключу;
  - обработанные инкрементальные файлы перемещаются в `increment/done/`, чтобы
    не быть обработанными повторно.
- Демо-инкремент:
  - скрипт `scripts/build_increment_sample.py` выбирает случайную подвыборку из
    `processed/final_anxiety_dataset.parquet`, заменяет идентификаторы респондентов
    на новые и сохраняет её в `data/increment/anxiety_increment.parquet`;
  - при отсутствии флага `--no-upload` та же выборка загружается в MinIO в префикс
    `increment/`, откуда подхватывается DAG'ом.

## 7. Структура каталога `lab1` (ключевые пути)

- `docker-compose.yml`, `Dockerfile` — инфраструктура (Airflow + MinIO + Postgres).
- `dags/` — определение DAG `anxiety_preprocessing_pipeline`.
- `scripts/` — утилиты работы с MinIO и реализация стадий предобработки/инкремента.
- `data/raw/`, `data/increment/` — локальные данные (сырые и инкрементальные).
- `notebooks/` — EDA по данным опроса (исследование шкал, корреляций, распределений).
- `README.md` — инструкция по запуску инфраструктуры и пайплайна.
